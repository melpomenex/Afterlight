# Social place framework design

## Context

See proposal.md and program.md for evidence and the migration matrix. This design targets the actual `setRoom`/`currentWorld` implementation, not the obsolete courtGroup guide. Worlds already expose `{group, obstacles, items, update, setNodeStates?, screenQuad?}`. Keep the imperative Three.js client and NetworkClient. There is one transport topic, one RoomServer roster and several specialized durable domains. All coordinates below are x/z unless a y is explicit.

## Goals / Non-Goals

Goal: a fifth destination requires one manifest entry, builder, atmosphere selection and tests, not new travel/presence code. Narrow extractions must leave intermediate commits buildable. No ECS, React, TypeScript, scene graph serialization, assigned-seat reservation, social graph, new chat service or wholesale main.js rewrite. Definitions support `environment`, `venue`, `view`; only environments and Theater venue ship now.

## Decisions

### D1 — Plain manifest around existing builders

Add **shared/placeDefinitions.js** (new, no Three.js/DOM imports) exporting immutable public `PLACE_DEFINITIONS`, lookup and validation. Store common display metadata, stable ID/kind, numeric geometry seed, bounds, two safe spawns, explicit exits, minimap path, atmosphere preset key, capability booleans and legacy classification here. Migrate existing district plain definitions into this module and have `src/districts.js` re-export `districts` for compatibility. Freeze the original 17-entry ordering as `LEGACY_DISTRICT_IDS`; Desert appends to the public definition list without changing this list or seeds. Preserve old numerical seeds as explicit values (`oldIndex * 37`), including zero for court.

Concrete shape (new definition example, not current code):

```js
{ id:'desert-camp', name:'Desert Camp', kind:'environment', seed:629,
  bounds:{minX:-11.3,maxX:11.3,minZ:-9.5,maxZ:10.3},
  spawn:[-9,0], companionSpawn:[-8.2,1],
  exits:[{id:'to-court',position:[-10.7,0],target:'court'}],
  minimapPath:'...', shell:'none', builderKey:'desertCamp',
  atmosphere:{preset:'desert-night',weatherMode:'fixed',timeMode:'fixed'},
  capabilities:{seating:true,sharedMedia:false,conferencing:true},
  social:{featured:true,legacy:false},
  objective:null, note:null }
```

Bounds belong to definitions; `getBoundsForRoom` delegates for registered public places, preserving explicit market/personal-garden compatibility and pure isWalkable/clamp/minimap. `garden` remains the explorable Glass Garden; `garden:<id>` remains personal cultivation, with `?room=garden` retaining its current personal-garden shorthand. No universal 25×22 shell for future views: shell `legacy-urban` retains current floor/walls/backdrop/lamps, `none` lets a builder author its complete environment using the same helper/context contract. Theater stays legacy-urban unchanged. A tiny test-only view uses smaller bounds and no gates to prove the schema does not force a district-sized level.

Validation rejects duplicate IDs, nonfinite/inverted bounds, missing builder keys, unsafe declared spawns, invalid exit targets, missing minimap, unknown capabilities/modes, and incomplete *present* objective/note tuples. Objective is optional for new social places. Existing twelve biome objectives/notes remain. Pure metadata validation cannot prove obstacle clearance: builder tests must do that. No user-supplied URLs, executable functions or arbitrary HTML in manifests.

**src/places/registry.js** maps builder keys and specialized controller keys to functions. It owns references, not metadata authority. Extend buildDistrict with shell selection and returned optional `environment` bindings (zones, material families, emitter anchors); keep legacy return fields. Static definitions are never copied into room mutation payloads.

Phoenix cannot import ES modules: add **scripts/export-place-definitions.mjs** producing a bounded committed **server_elixir/priv/place_definitions.json** subset (`schemaVersion`, ids, kind, public flag, bounds, atmosphere configuration only); **Afterlight.World.PlaceDefinitions** loads/validates at boot. `--check` compares generated bytes with committed bytes. This is a build-controlled projection, not a second editable manifest. No runtime YAML or network catalog fetching. Room resolution compatibility remains open for old tools; only known public definitions receive directory/atmosphere features.

### D2 — Prepare first, commit once

Add **src/places/runtime.js** with dependency-injected `createPlaceRuntime({resolve,build,scene,resetInput,placeActors,bindNetwork,present,...})`. `setRoom` becomes the existing public orchestration wrapper so callers and realtime join interception survive. Runtime keeps `{activeId,activeWorld,activationGeneration,phase}` and cache; main keeps renderer, actors, movement and UI orchestration. Separate **src/places/travelState.js** pure reset/transition helpers for headless tests. All consumers receive the same activeWorld/bounds.

Transition order:

1. Resolve destination. Valid deep link wins; absent link remains Theater. Unknown ID announces unavailable and resolves Theater, never market under a mismatched wire ID. Personal gardens resolve via their existing adapter.
2. Prepare destination world once, hidden; validate bindings and safe spawn/dismount data. Build failure disposes partial *owned* resources, leaves prior active world/membership and HUD intact, shows a persistent retryable travel error. No JOIN_ROOM yet.
3. Increment activationGeneration. Deactivate prior controller, stand the actor up locally, clear previous seat/cinema and effects/audio; close old place-specific dialogs through their existing cancellation methods. Call teardown must stop local capture immediately if a P8 adapter exists; its server leave is asynchronous and cannot block travel.
4. Hide old group and show destination; replace currentWorld/currentBounds; reset nearest, target, marker, held keys, pointer gesture/capture, queued jump/momentum, emote wheel/pose and garden-only frame inputs. Place player/Kiln at validated spawns; keep global actors/lights outside world groups.
5. Apply destination base atmosphere, bind desiredRoom through existing net.joinRoom, clear remote roster through existing realtime reset seam, update identity/minimap/canvas accessible name and local visited/current save. Do not change default reload behavior to last-place entry: absent query still Theater.
6. Activate optional systems with the current generation; announce local ready. Network status is separately `joining/online/offline`; joining is not claimed before accepted server evidence. Render continues offline, but shared actions are unavailable until membership/snapshot is restored.

Failed server join leaves the rendered destination accessible locally, marked offline/unavailable, and shared actions disabled; user can retry or select another place. Do not silently show the old room's participants. Rapid A→B→C travel discards async B work via generation check. Reconnect does not rebuild geometry or auto-start capture.

Garden updates remain stored for the garden adapter; district update gets only boolean completion, never `currentGardenBeds || isDone`. Legacy garden-world callbacks receive beds explicitly. A late GARDEN_STATE may refresh the cache but cannot alter active district update input.

### D3 — Network transition boundary on game:v1

Keep `joinRoom(roomId)` and hello-before-desiredRoom replay. No new room socket or client Presence manager. To prevent queued output crossing travel, change internal World messages to carry source wire room ID: `{world_frame, room_id, frame}`. GameChannel verifies room_id equals its current assigned world before forwarding or converting to rt_binary. Add roomId to public JSON presence frames and outer rt_binary event metadata, not the SoA bytes. Update Phoenix adapter to discard mismatched outer roomId before handleBinary; preserve its old-server fallback when absent. New server and client tests cover old queued A output after B join, including binary conversion. Do not alter binary headers/ABI.

Client new features compare explicit frame.roomId to desiredRoom before epoch checks; use roomId as the epoch key for tagged frames. Do not blanket-drop untagged historical WELCOME or Theater/catalog replies. Keep P5/P7 specialized handling; no invented generic room_snapshot replaces their snapshots. The framework's public-room JOIN can use the targeted directory/atmosphere response plus tagged roster as acceptance evidence, with no extra authority.

### D4 — Theater adapter, not generic media

Add **src/places/theaterAdapter.js**, injected with the existing TheaterScreenUI singleton. Activate calls setRoomActive(true) and existing default setWatchMode(true); deactivate calls setSeated(false), setWatchMode(false), setRoomActive(false), updateScreenQuad(null) and closes owned open booth/guide/picker dialogs through their cleanup methods. Do not destroy and reconstruct the UI on each visit or clear personal playlists/catalog caches. Preserve existing handlers, `applyState`, timeline/drift, `loadToken`, torrent grants, resolution preview/confirm, IPTV lazy pull, EPG interval lifetime and fallbacks.

Keep screenQuad projection after camera update using activeCamera. Adapter handles seat-change notifications only when active in Theater; external benches cannot invoke cinema. Headless tests are insufficient for playback: execute verification.md's media matrix on isolated test rooms/data. Existing Theater effects and restoration remain optional, untouched.

### D5 — Explicit seats and a bounded interaction registry

Add **src/social/seating.js** with pure normalizeSeat/chooseDismount and one injected seat controller. New item `{type:'seat',id,x,z,sit:{x,y:0,z,rotY},dismount:[{x,z}],groupId,acousticZoneId,animationProfile:'folded'}`. Position y stays zero to preserve the existing avatar/remote seated pose; benches are authored to match. Dismount list 1–4 authored candidates; first walkable wins, otherwise validated world spawn. Seats need no durable IDs/occupancy locks, and overlapping occupants are allowed. Never label a seat reserved/free based on local overlap.

Theater's missing metadata normalizes to sit x=seat.x, z=seat.z−0.08, rotY=PI and dismount `(x,z−0.8)`, exactly current behavior. Other seats require explicit poses. Movement/E/Space/click/Escape/travel cleanly end sitting; first movement press preserves existing stand-before-walk handling; chat focus cannot swallow escape. Existing sitting/airborne fields and emotes remain the sole pose wire representation; do not add seat reservations or network seat IDs. Test the 80ms movement throttle so stand/sit is ultimately transmitted even when its immediate send is throttled.

Add **src/social/interactions.js**: map known new/generalized item types to handlers receiving injected active context. Register seats, gates, notes and specialized screen delegation; unknown types return unhandled and existing legacy dispatch runs. It is not an arbitrary plugin script loader. No new wave/point protocol: `shared/emotes.js` already owns six choices.

### D6 — Resources and one update loop

World cache remains lazy and retained for geometry initially. Each controller has activate(context), update(dt,serverNowMs), deactivate(), dispose(); deactivate/dispose idempotent. Only active controller receives updates. Main's rAF is the only animation loop. Deactivation stops audio sources, event timers and GPU update writes immediately (audio can ramp down for at most 200ms); cached static geometry remains allocated. B owns one active atmosphere effect allocation set, disposes/recreates it on travel; hidden weather fields do not remain allocated per cached district. No automatic legacy-world eviction yet: module-level node material cache is shared and naive traversal disposal could invalidate other worlds. Track owned resources explicitly; dispose only those, on failure/unmount or future explicit eviction. Avoid per-frame allocations in newly extracted update paths. Legacy cached geometry growth is measured, not described as free.

### D7 — Voice-ready means inert metadata

Define zones/group IDs now; inject an optional call adapter with `onPlaceLeaving(roomId)`, `onPlaceReady({roomId,zones,seatGroup})` and `subscribeMixState(listener)` returning unsubscribe. No implementation of calls.js, callPanel, CallChannel or workers in A. Missing adapter is a no-op. P8 must supply it only after its gate and use existing Call.room_key / World.RoomKey, deriving membership server-side. `onPlaceReady` updates association options, never joins/publishes. Leaving stops capture, clears duck requests, and invokes P8 leave/revoke; no default cross-place calls. Acoustic attenuation is comfort metadata; no privacy promises before P8 enforces server subscriptions. Call capacity remains P8's tested cap, separate from place occupancy.

### D8 — Truthful directory without new presence

Add read-only `place_directory_get {requestId}` and targeted `place_directory {requestId,serverNow,entries:[{roomId,occupancy,observedAt,atmosphereLabel?,activity?}]}`. requestId string ≤64; no client list/URLs. Signed game session required, one in-flight request, minimum 5 seconds between requests. Max 64 public manifest entries and 16KiB response; reject over-cap deployment configuration at boot rather than silently hide entries. Registry lookup does not start idle rooms. On supported single-node topology absent known room = 0; active room count = RoomServer roster_size (unique identities, self included). Timed-out/crashed/routable-remote owner = null. Read through existing World TaskSupervisor with concurrency 4, each call ≤100ms and total deadline 500ms; cancel overdue work. Use real room owner resolution when multi-node is enabled, otherwise null, never infer global totals from local Registry. No capacity enforcement in A: omit capacity from cards until a separately tested admission policy exists.

Place summaries are snapshots, not a presence subscription. Poll while dialog open every 10s, cancel on close/disconnect; data older than 30s is unknown. Prevent late replies updating a closed/reopened dialog with request generation. Never retain private garden counts or expose player IDs. P5 can provide an optional bounded current title only through its domain query; first release omits activity outside locally current Theater because there is no ready directory-wide activity projection. Do not query catalogs or invent now-showing titles. Atmosphere labels use known static metadata in A, server summary in B; label defaults as such if authoritative state unavailable.

Selector remains a compact modal over full-window world, T/Travel access unchanged. Featured destinations first (Theater, court initially, Desert and rooftops only after acceptance); expandable Legacy areas retains all older destinations plus market/personal garden and visited/restored badges. No unavailable cards for future places. DOM textContent for dynamic counts/activity; no server strings in innerHTML. Native dialog cancel, focus return and narrow scroll work. No friend counts or avatars of nonexistent occupants.

## Risks / Trade-offs

- [Lifecycle refactor touches input and media] → dependency injection and behavior tests before extraction, then real browser matrix.
- [Open room names remain accepted server-side] → feature projection allow-list; no global compatibility change to room resolution in this program.
- [No capacity enforcement] → report counts only; hot-room capacity remains measured upstream work.
- [Legacy caches persist] → explicit resource ownership and soak evidence; do not falsely claim an LRU exists.
- [Old server lacks directory/tagged frames] → unknown metadata, retain compatibility; release acceptance targets Phoenix, not Node-only.

## Migration Plan

Manifest and tests → explicit unchanged legacy routes/seeds → runtime reset seam → generalized seats/Theater adapter → tagged room output/directory → selector/docs/regressions. Preserve localStorage container fields, `afterlight-save`, personal lists and all snapshot files. Rollback client presentation/build without changing backend authority; extra directory messages can be disabled, old clients ignore additive metadata. No changes to existing migration tasks/status in this planning session.

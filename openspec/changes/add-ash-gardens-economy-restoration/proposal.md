# Add Ash Gardens, Economy & Restoration Domains

## Why

The game's entire transactional core — wallets, inventory, the NPC market, the player order book, contracts, garden growth, gather nodes and the mill — lives in `server/economy.js`, `server/orderbook.js`, `server/gardens.js`, `server/nodes.js`, `server/machines.js` and the ad-hoc handlers in `server/index.js`, persisted as one synchronously-rewritten `data/game-state.json`. Money and items are mutated by free-floating arithmetic on shared JSON objects, then the whole file is rewritten on nearly every message. There are no constraints, no transactions, and no reservations ledger: two buyers racing one resting sell order can both read "5 remaining" and both get credit; a crash mid-`order_place` can strand escrow; every save serializes all 26 players' state for every garden tick.

This is the critical migration phase (P6 in `docs/architecture/elixir/ownership.md`, rows 5–11): gardens (#5), wallets/inventory (#6), the NPC market (#7), the order book/trades/fees (#8), contracts (#9) and restoration nodes/machines (#10–11) move to `Afterlight.Gardens`, `Afterlight.Economy` and `Afterlight.Restoration` on PostgreSQL **as one atomic authority group**. Money correctness becomes a database property — integer columns with nonnegative constraints, explicit reservation columns, one deterministic-lock-order SQL transaction per market fill, idempotency receipts, and an at-least-once outbox — instead of an application-level hope. Player-visible behavior does not change: the wire payloads (`garden_state`, `inventory_state`, `market_update`, `contract_update`, `node_state`, `machine_update`, `action_result`, `trade_filled`, `error`) and every error reason string stay byte-compatible, and the deterministic rules (growth, prices, rounding, matching priority, contribution clamps) are proven against the P0 parity fixtures before authority flips.

## What Changes

- **One transactional authority group flip**: routing for `garden_action`, `market_buy`, `market_sell`, `order_place`, `order_cancel`, `contract_complete`, `node_harvest`, `machine_contribute`, `machine_mill`, `machine_craft` (and their server→client payloads) moves from Node to Phoenix in a single cutover; the corresponding Node write paths are disabled in the same change. No partial split of the group is allowed — a garden harvest credits inventory, and a contract consumes it, so half the group on each backend would corrupt both.
- **PostgreSQL money model**: new `wallets` (integer `coins`, integer `reserved_coins`) and `inventory_balances` (one row per player/item/kind, nonnegative, explicit `reserved` pools as separate kinds) tables with database CHECK constraints; player inventory jsonb from the frozen `game-state.json` snapshot is normalized into balance rows in this change. Every escrow is an explicit column/kind: `reserved_coins` for resting buy orders, `reserved_produce` balance rows for resting sell orders.
- **The market fill is one SQL transaction** (bounded raw Ecto behind an `Afterlight.Economy` domain function): buyer/seller balances, reservations, both inventories, order remainders, fee (`max(1, round(value*0.02))`), trade row, ledger entries, command receipt and outbox event commit or roll back together, serialized per crop market by a transactional advisory lock with a documented lock ladder. Oversell and negative balances are database-enforced, and retries are idempotent via `(actor, request_id)` receipts.
- **Gardens on persisted timestamps**: 12 beds per player in `gardens`/`beds`/`sprinklers` tables; growth stage derives from `planted_at` + tick math identical to `shared/gardenModel.js` (moisture/health float accumulation at 1 Hz, rain flag from the world runtime, sprinkler coverage); harvest commits bed state + produce credit + xp/level in one transaction. Current semantics are ported faithfully — including that only the stage self-catches-up while a garden is offline; deterministic moisture catch-up is explicitly a follow-up.
- **NPC market and multipliers**: `npc_buy`/`npc_sell` with `js_round` price parity (0.85 sell discount, 0.4-damped seed price), `toFixed(3)` multiplier parity (±0.2/−0.5 per unit, mean reversion 0.05, clamp 0.4–2.5) persisted per item in `market_multipliers`.
- **Order book and trades in PG**: `orders` indexed by `(crop_id, side, price, created_at)` for price-time matching with maker-price execution, crop-mismatch break, self-match allowed — all current quirks preserved; `trades` and `ledger_entries` make every coin/item movement auditable; the client `orderId` becomes the durable `request_id`.
- **Contracts board gains durability (additive)**: the 3-slot board, which today is regenerated in memory at boot and lost on restart, is persisted in a `contracts` table with the 5-minute reroll cadence persisted too; 10-minute `expires_at` continues to be generated exactly as today. This is new durability, not a behavior change.
- **Restoration**: `gather_nodes` (9 nodes / 3 districts / 180 s respawn, depletion timestamps persisted), harvest race resolved by a conditional row update (first player wins, second gets `node_depleted`); `machines`/`machine_materials`/`machine_contributions` with the exact clamp `applied = min(requested, held, remaining)`, restore-in-same-step, and an audit row per contribution; `mill_wheat` grade order C→B→A→A+; `craft_sprinkler` at copper 2 + glass 2.
- **Import ceremony**: `game-state.json` players/gardens/orders/trades/marketMultipliers/nodes/machines are imported idempotently under a write freeze (snapshot + hash), with conservation validation (coins + reservations reconcile, inventory reconciles per player, order escrow reconciles against reserved pools) before the router flips.

Depends on: `add-ash-theater-catalog-domains` (P5 — the Elixir app, gateway, parity runner and freeze→import→flip ceremony it builds on are prerequisites; no requirement in those specs changes). Also builds on `add-ash-accounts-domain` (P4 durable sessions, signed identity, command receipts — with P4 narrowed to session authority, the `players` rows themselves activate with this change's group flip) and `add-world-room-runtime` (P3 room ownership; weather authority transfers to the runtime with this flip, feeding the garden tick).

## Capabilities

### New Capabilities
- `gardens-domain`: Server-authoritative personal gardens as player-facing behavior — tilling/planting/watering/harvesting the 12-bed plot, seed and sprinkler-kit consumption, growth stages from persisted timestamps, moisture/health tick parity (including rain), sprinkler placement and coverage, offline behavior, and atomic harvest rewards.
- `economy-domain`: Wallets, inventory, the NPC market, the player order book, trades and the contract board as player-facing behavior — instant buy/sell with dynamic prices, escrowed limit orders with price-time matching and fees, contract completion rewards, and the guarantee that every fill is one transaction that cannot oversell, lose coins, or double-apply a retried command.
- `restoration-domain`: Gather nodes and shared machines as player-facing behavior — harvesting copper/timber/glass across the three districts with persisted respawn timers, contributing to the Great Mill's restoration bill with audited clamped contributions, milling wheat into flour, and crafting sprinkler kits.

### Modified Capabilities
- (none — the three capabilities above are new; the `migration-governance` requirements in `port-backend-to-elixir` are constraints this change satisfies, not capabilities it modifies. The P4 accounts spec is not altered: its `Player` resource is activated as writer by this change's group flip, exactly as the narrowed P4 scope declared.)

## Impact

- **Elixir (new)** — under the Phoenix application root from `add-elixir-phoenix-foundation`: `Afterlight.Gardens` (Ash domain + `water_bed`/`plant_bed`/`harvest_bed`/`place_sprinkler`/`till_bed` actions, 1 Hz tick server), `Afterlight.Economy` (Ash domain + `npc_buy`/`npc_sell`/`place_order`/`cancel_order`/`complete_contract`; `Afterlight.Economy.Pricing` parity math; `Afterlight.Economy.MarketFill` bounded raw-SQL transaction; contracts board), `Afterlight.Restoration` (`gather`, `contribute_to_machine`, `mill_wheat`, `craft_sprinkler`), migrations for `gardens`, `beds`, `sprinklers`, `wallets`, `inventory_balances`, `market_multipliers`, `orders`, `trades`, `ledger_entries`, `contracts`, `gather_nodes`, `machines`, `machine_materials`, `machine_contributions`, plus receipt/outbox reuse from P4; `Afterlight.Import.EconomyGroup` importer + `mix afterlight.import_economy_group` task (single frozen-snapshot import of all economy-group domains incl. players); parity runner suites for gardenModel/economy/orderbook/nodes/machines; StreamData property + concurrency test suites; market contention benchmark script.
- **Elixir (modified)** — gateway router/domain map (flip the whole group atomically), welcome/snapshot builders (`garden_state`, `inventory_state`, `market_update`, `contract_update`, `node_state`, `machine_update` payloads), world runtime (weather authority and its flag feeding the garden tick land with this flip), P4 `players` rows activated from the frozen-snapshot import (inventory jsonb normalized into balance rows here).
- **Node (modified, same release)** — `server/index.js` handlers for the ten command types are frozen at the flip (retryable busy), disabled after it, and deleted only by `remove-node-server-authority` (P11) for migrated clients; `server/gardens.js`, `server/economy.js`, `server/orderbook.js`, `server/nodes.js`, `server/machines.js` write paths disabled after flip; `data/game-state.json` gardens/orders/trades/marketMultipliers/nodes/machines/player-wallet slices become read-only and are no longer written.
- **Client**: none — `src/net/client.js` helpers, message shapes, reason strings and `garden:<guestId>` room semantics are preserved by the transport adapter; `src/ui/marketModal.js` keeps previewing server prices (price parity is user-visible).
- **Persistence**: `data/game-state.json` loses the six migrated state slices (kept read-only for the reverse export tool); PostgreSQL becomes the sole writer.
- **Docs**: `docs/architecture/elixir/ownership.md` rows 5–11 marked flipped on cutover; protocol catalog notes the authority change (no wire change).
- **Tests**: existing JS tests stay green until flip; new parity fixture runs, real-PostgreSQL integration tests, StreamData conservation/concurrency properties, and the contention benchmark (p95 fill ack < 250 ms same-region) gate the flip.
